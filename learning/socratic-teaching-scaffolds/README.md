## 目的

苏格拉底式教学脚手架通过策略性提问和渐进式移除支持，引导学习者通过主动发现获取知识。

这项技能旨在：

- 将被动解释转化为主动发现
- 通过揭示矛盾纠正错误观念
- 通过学习者自己形成的见解建立更持久的理解
- 随着学习者能力提升，逐步减少外部指导

## 何时使用

### 适用场景

在以下场景中使用此技能：

- 教授更强调理解而非记忆的复杂概念，例如算法、科学理论和哲学思想
- 纠正难以通过直接解释消除的深层错误观念，例如统计谬误、物理直觉和错误的编程心理模型
- 帮助学习者发展问题解决能力，而不仅仅是获得某个问题的答案
- 设计从具体经验逐步过渡到抽象理解的学习体验
- 通过引导式发现而非大量文档培训专业人员
- 创建带有内置反馈循环的自定进度学习材料
- 通过提问培养学习者的独立思考能力
- 帮助不同知识水平的人跨越专家与初学者之间的认知差距

### 常见触发语句

用户可能使用以下表达：

- “教我 `[概念]`”
- “帮助我理解 `[主题]`”
- “解释得像我是 `[专业水平]`”
- “我不明白为什么 `[错误观念]`”
- “学习 `[技能]` 的最佳方式是什么？”
- “我应该如何思考 `[概念]`？”

## 这是什么

这是一个结合了 **苏格拉底式提问（Socratic Questioning）** 和 **教学脚手架（Instructional Scaffolding）** 的教学框架。

- **苏格拉底式提问**：通过策略性问题引导学习者主动发现答案
- **教学脚手架**：提供临时支持，并随着学习者能力增长逐渐减少支持

### 核心组件

1. **问题阶梯（Question Ladder）**  
   从简单到复杂逐步递增，通过连续问题构建理解。

2. **错误观念探测器（Misconception Detector）**  
   通过反例、预测和矛盾暴露错误心理模型。

3. **费曼解释（Feynman Explanation）**  
   从简单类比逐步过渡到技术上精确的解释。

4. **消退式工作实例（Faded Worked Examples）**  
   按以下路径逐渐减少帮助：

   ```text
   完整解决方案 → 部分解决方案 → 独立练习
   ```

5. **认知学徒制（Cognitive Apprenticeship）**  
   首先显式展示思考过程，然后逐渐将任务控制权交给学习者。

### 快速示例：教授递归

#### 问题阶梯

1. “你能将这个问题分解成其自身的较小版本吗？”  
   → 问题分解

2. “如果只有一个项目会怎样？”  
   → 基础案例发现

3. “如果我们能解决较小版本，如何利用它解决较大版本？”  
   → 递归案例

4. “什么能够阻止这个过程永远运行下去？”  
   → 终止条件推理

#### 错误观念探测器

> “这个递归会停止吗？尝试用 3 个项目追踪它。”

用于揭示对无限递归或终止条件的错误理解。

#### 费曼式解释进展

- **级别 1**：像俄罗斯套娃——每个娃娃里面都有一个更小的版本
- **级别 2**：函数使用更简单的输入调用自身，直到到达基础情况
- **级别 3**：递归定义为 `f(n) = g(f(n-1), n)`，其中 `f(0)` 为基础情况

## 工作流程

可以复制以下清单跟踪教学进度：

```text
苏格拉底教学进度：

- [ ] 步骤 1：诊断学习者当前理解
- [ ] 步骤 2：设计问题阶梯和脚手架计划
- [ ] 步骤 3：通过提问引导发现
- [ ] 步骤 4：随着能力增长逐渐撤除脚手架
- [ ] 步骤 5：验证理解和知识迁移
```

### 步骤 1：诊断学习者当前理解

通过探测性问题识别：

- 当前知识水平
- 已有心理模型
- 潜在错误观念
- 学习目标
- 对相关前置知识的掌握程度

参见：[苏格拉底式问题类型](#苏格拉底式问题类型)。

### 步骤 2：设计问题阶梯和脚手架计划

设计一条从学习者当前状态到目标理解状态的认知路径。

对于较直接的教学任务：

- 使用 [`resources/template.md`](resources/template.md)

对于包含多个错误观念或较复杂的主题：

- 使用 [`resources/methodology.md`](resources/methodology.md)

### 步骤 3：通过提问引导发现

按照问题序列逐步推进。

根据学习者的状态适时提供：

- 提示
- 类比
- 反例
- 工作实例
- 部分解决方案
- 中间步骤

参见：[脚手架级别](#脚手架级别)。

不要机械执行预设问题列表，应根据学习者的回答动态调整后续问题。

### 步骤 4：随着能力增长消退脚手架

随着学习者能力提升：

- 减少提示
- 提供不完整示例
- 增加开放性问题
- 逐渐要求独立推理
- 从“告诉下一步”转向“让学习者决定下一步”

持续区分两种状态：

- **生产性挣扎**：存在挑战，但可以通过有限引导解决
- **挫败状态**：难度过高，当前脚手架不足

详细策略参见：

- [`resources/methodology.md`](resources/methodology.md)

### 步骤 5：验证理解和迁移

通过新的问题确认学习者是否真正掌握概念，而不是仅仅记住当前例子的答案。

可以要求学习者：

- 用自己的话重新解释概念
- 解决一个新的问题
- 给出自己的例子
- 分析边缘情况
- 预测改变条件后的结果
- 解释为什么某个错误答案是错误的
- 将概念教授给另一个人

可以使用以下评估标准进行自检：

- [`resources/evaluators/rubric_socratic_teaching_scaffolds.json`](resources/evaluators/rubric_socratic_teaching_scaffolds.json)

最低标准：

```text
平均得分 ≥ 3.5
```

## 苏格拉底式问题类型

### 1. 澄清性问题

目的：理解学习者当前的思考。

示例：

- “你所说的 `[术语]` 具体是什么意思？”
- “你能给我一个例子吗？”
- “这与 `[已知概念]` 有什么关系？”

### 2. 探究假设

目的：揭示隐藏的前提和默认信念。

示例：

- “我们在这里假设了什么？”
- “为什么这个假设会成立？”
- “这在所有情况下都成立吗？”

### 3. 探究理由与证据

目的：检查某个结论的依据。

示例：

- “你为什么这么认为？”
- “有什么证据支持这一点？”
- “我们可以如何测试它？”

### 4. 探究含义

目的：进一步推导一个观点的后果。

示例：

- “如果 `[条件]` 改变，会发生什么？”
- “从这一点还能推出什么？”
- “它有哪些边缘情况？”

### 5. 质疑问题本身

目的：促进元认知。

示例：

- “为什么这个问题重要？”
- “我们真正想理解的是什么？”
- “我们如何知道自己已经理解了？”

### 6. 揭示矛盾

目的：通过认知冲突帮助学习者发现错误观念。

示例：

- “你刚才说了 `[X]`，但现在又得到 `[Y]`，这两者如何同时成立？”
- “如果那个结论是真的，为什么 `[反例]` 会发生？”
- “按照你的模型，它会如何预测 `[测试案例]`？”

## 脚手架级别

根据学习者当前需求提供适当支持，并随着能力提升逐步消退。

### 级别 5：完整建模

**我做，你看。**

适用于学习者尚未掌握基本方法的情况。

提供：

- 带完整思考过程的工作实例
- 明确的策略说明
- 所有关键步骤
- 每一步背后的理由

### 级别 4：引导实践

**我做，你帮助。**

提供：

- 部分工作实例
- 要求学习者补充某些步骤
- 在可能出错前给予提示
- 通过选择题式问题缩小搜索空间

### 级别 3：指导实践

**你做，我帮助。**

学习者首先独立尝试。

教师仅在卡住时：

- 提出引导问题
- 提供有限提示
- 帮助定位问题

尽量避免直接给出答案。

### 级别 2：独立反馈

**你做，我观看。**

学习者独立完成任务。

完成后：

- 审查解决过程
- 分析成功和失败原因
- 讨论其他可能的方法
- 识别下一轮需要改善的部分

### 级别 1：转移

**你教别人。**

要求学习者：

- 向他人解释概念
- 自己创建示例
- 设计练习题
- 在他人的推理中识别错误观念

### 消退策略

默认不要从级别 5 开始。

应从与学习者当前能力匹配的级别开始。

基本原则：

```text
学习者持续成功
    ↓
降低一级脚手架

学习者重复失败
    ↓
提高一级脚手架
```

目标不是提供尽可能多的帮助，而是提供**完成当前任务所需的最少帮助**。

## 常见模式

### 模式 1：概念引入

```text
具体 → 抽象
```

过程：

1. 从现实世界类比或具体示例开始
2. 引入正式术语
3. 建立抽象模型
4. 最后讨论边缘情况

示例：

```text
教授指针：

信封地址
    ↓
内存地址
    ↓
指针
    ↓
解引用
    ↓
指针算术
```

### 模式 2：错误观念纠正

```text
预测 → 惊喜 → 解释
```

过程：

1. 要求学习者预测结果
2. 展示实际结果
3. 如果预测错误，引导其观察矛盾
4. 构建正确心理模型

示例：

> “你认为 `0.1 + 0.2` 的结果是什么？”

然后观察实际结果，并继续追问：

> “为什么它不是精确的 `0.3`？”

### 模式 3：问题解决策略

```text
建模 → 实践 → 反思
```

过程：

1. 在简单问题上展示完整策略
2. 让学习者在类似问题中应用
3. 提供必要指导
4. 反思该策略何时适用以及何时失效

示例：

```text
教授调试：

打印日志
    ↓
定位异常区域
    ↓
设置断点
    ↓
提出假设
    ↓
设计实验验证假设
```

### 模式 4：深度阶梯

```text
ELI5 → 本科 → 专家
```

为同一个概念构建多个解释层次。

例如教授神经网络：

```text
模式匹配
    ↓
加权和
    ↓
矩阵运算
    ↓
反向传播
    ↓
优化理论
```

允许学习者选择起点，并在每一级提供继续深入的路径。

### 模式 5：发现学习

```text
谜题 → 提示 → 见解
```

过程：

1. 呈现一个现象或谜题
2. 让学习者尝试解释
3. 如果卡住，逐步提供提示
4. 引导学习者自己发现核心规律

示例：

```text
汉诺塔
    ↓
如何移动 n 个盘子？
    ↓
先思考 n - 1 个盘子
    ↓
发现子问题结构
    ↓
得到递归解法
```

## 护栏

### 近期发展区

难度需要控制在合适范围：

```text
太容易 → 无聊
适度困难 → 生产性挣扎
太困难 → 挫败
```

理想状态是：

> 学习者无法完全独立完成，但能够在适当引导下完成。

根据学习者的挣扎程度动态调整脚手架级别。

### 不要钓鱼特定答案

苏格拉底式提问不是猜谜游戏。

不要为了让学习者猜出教师预设的某句话，而不断提出含糊问题。

如果学习者：

- 推理合理
- 使用了不同方法
- 得出了不同但有效的结论

应该探索其思考路径，而不是强行拉回预设答案。

### 避免伪教学

不要为了“表现得像苏格拉底教学”而不停提问。

每一个问题至少应该完成以下目标之一：

- 推进理解
- 揭示假设
- 检验证据
- 暴露矛盾
- 引导下一步推理
- 检验是否真正理解

如果继续提问已经没有帮助，应直接提供解释。

### 错误观念抵抗

深层错误观念通常不会因为一次纠正就消失。

可能需要：

1. 多次预测
2. 多个反例
3. 多次认知冲突
4. 重建正确心理模型
5. 再回头分析原有错误模型为什么错误

必要时，应先从零构建正确模型，而不是一直围绕错误模型进行修补。

### 专家盲点

专家经常忘记初学者真正困难的地方。

需要主动：

- 将隐式知识显式化
- 拆分自动化的思考过程
- 放慢推理速度
- 展示中间步骤
- 解释为什么选择某一步，而不仅仅是展示这一步

### 个体差异

不同学习者对教学方式的偏好不同：

- 有些人偏好探索
- 有些人偏好明确结构
- 有些人适合大量实例
- 有些人更适合抽象模型

因此需要动态调整：

- 提问密度
- 提示程度
- 解释长度
- 示例数量
- 脚手架级别

持续监控：

```text
生产性挣扎 ↔ 挫败感
```
