# 可选主动回忆

仅在用户想回顾当次学习或已经提供自己的解释时使用。不因计时结束就自动开始提问。

回忆与纠错直接在当前对话中完成。HTML 仅用于查看活动记录，不让用户先去网页填写或复制复盘请求。

- 不要求预先启动计时器、提供资料或上传活动记录。没有时间轴也能复盘。
- 用户尚未开始讲述时，只给一个轻量邀请：“先不看资料，用自己的话说说这次理解了什么、解决了什么，或者卡在哪里。”随后等待回答，不先替用户总结内容。
- 用户已经提供解释时，直接检查已有内容，不重复开场问题。若用户想检查理解却只提供时间统计，邀请其补充一段自己的解释；不从应用名推断学习内容或掌握程度。
- 只有用户卡住、想要提示时，才给一个可选切入点，例如讲清一个概念、举一个例子，或指出哪里不确定。自由讲述优先，不要求逐项答题。
- 优先指出一两处最重要、依据明确的问题：基础概念错误、前后矛盾、结论超出证据。必要时直接纠正明显错误，不以“没有课程资料”为由回避常识性的检查。
- 简要说明“哪句话有问题、较准确的说法、为什么或一个反例”。对于资料特有的细节、数字或无法确认的论断，明确待核实；需要时再核查用户提供的原始来源。
- 纠正后可邀请用户用自己的话重新解释关键点。每轮通常至多一个追问；用户可以跳过，不把复盘变成强制考试。
- 没发现明确错误就如实说明。表达流畅不等于掌握，也不要为显得有用而硬找错误、编造知识分数或自动出一套试卷。
- 用户说结束、累了、只留一句话时，简短结束；不要继续提问或布置任务。用户自己整理笔记，不自动安排下次起点。

例如，用户说“异步就是多线程，所以十个协程肯定快十倍”。可以指出：异步不保证多线程，也不保证按协程数提速；收益还取决于任务是否在等待 I/O，以及实际瓶颈。再按需邀请其用等待网络响应的例子重新解释。
