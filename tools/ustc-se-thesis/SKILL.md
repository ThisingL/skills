# 中国科学技术大学软件学院专业硕士学位论文撰写 Skill（2026版）

## 何时使用本 Skill

以下任一场景触发：

- 撰写、修改、审校 USTC 软件学院专业硕士学位论文（开题、初稿、定稿、盲审、答辩稿）。
- 基于 `ustcthesis` LaTeX 模板排版或解决编译/格式问题。
- 为论文绘制 UML 图（用例图、类图、时序图、活动图、状态图、组件图、部署图等）。
- 论文章节组织、参考文献规范、图表编号、字数字体、查重率检查。
- 对照"论文存在问题与修改明细"做一致性/规范性自查。

---

## 一、总体要求（写作之前必须确认）

### 1.1 基本指标

- **字数**：硕士学位论文正文一般 **不少于 3 万字**。
- **篇幅**：正文页数 **60~80 页**。
- **查重**：初稿 **<30%**；定稿（盲审版）**<10%**。
- **真实性**：参考文献必须真实、规范，**禁止编造**；内容须有文献来源。
- **原创图**：除系统截屏外，文中所有图必须用 Visio 或 Rose 自行绘制，**严禁直接使用别人的图**。
- **禁入内容**：任何技术性、百科式、知识性介绍性内容不出现在正文（可作附录）。

### 1.2 语言与行文

- **人称**：不用"我""我们"，改用 **"本文"** 或"本人"；不用"本论文""本次论文"。
- **专业表达**：通顺、不口语化（禁用"是……的话"）；无错别字；避免孤句孤行孤段。
- **英文缩写**：首次出现须先全称后缩写；全文大小写一致（SQL 不要与 Sql 混用）。
- **标题**：除非必要，**不要使用"基于 XXX 的…"**；一般缩写词不宜直接放入标题/关键词。
- **一致性**：需求分析→概要设计→详细设计→测试，**模块划分必须一一对应、顺序一致**；非功能需求与其测试必须对应；各章节之间禁止冗余描述。

## 二、论文结构（章节组织，除第 1 章和末章外，每章末必含"本章小结"）

```
封面 → 原创性声明 → 授权使用声明 → 中文摘要 → 英文 Abstract
→ 目录 →（图表清单，可选）→ 引言（专业硕士可省）
→ 第1章 绪论
→ 第2章 相关技术分析与平台介绍（而非"简介/概述"）
→ 第3章 需求分析
→ 第4章 系统概要设计
→ 第5章 系统详细设计与实现
→ 第6章 系统测试
→ 第7章 总结与展望
→ 参考文献 → 附录 → 致谢 → 在读期间发表的学术论文与取得的其他研究成果
```

### 2.1 封面、声明、摘要、目录

- **封面/声明**：统一模板，涉密须标密级，必须亲笔签名。
- **中文摘要**：约 600 字；四要素 **目的 / 方法 / 结果 / 结论**，突出作者贡献，**不能写成产品说明书**；不含公式、图表、文献。
- **英文 Abstract**：`paper` 改为 `thesis` 或 `dissertation`；关键词间用逗号。
- **关键词**：3~8 个（中文空格分隔、英文逗号分隔），为可检索的代表性技术词。
- **摘要页留白**：不超过页面三分之一。
- **目录**：只有一个子节时取消该子节层级（如 2.5 下只有 2.5.1 则不保留 2.5.1）。

### 2.2 第 1 章 绪论

- **1.1 背景与意义**：体现研究的必要性与迫切性。
- **1.2 国内外研究现状**：**不少于 1 页**；**立足于技术**；禁止简单罗列，必须归纳分析，引出要解决的问题。
- **1.3 主要问题**。
- **1.4 本文/本人主要工作**：详写、不夸大、不只写"参与"，须与后文一一对应。
- **1.5 论文组织结构**：研究型论文需附 **组织架构图**。
- 参考文献标注主要集中在本章。

### 2.3 第 2 章 相关技术分析与平台介绍

- 章名为"**分析**"（不是"简介""概述"）。
- 不是知识点复述，而是 **选型依据**：为何采用该平台/框架，解决什么问题，优势何在。
- 本章小结应回答"为什么选择这些技术"。

### 2.4 第 3 章 需求分析

- **严禁**本章出现"模块"二字（模块属于概要设计）。
- 必有明确的 **需求导出** 描述。
- **参与者 (Actor)**：按企业职责细分具体角色，不能抽象写"用户/管理员"；用例图中 Actor 与用例之间用 **不带箭头的实线**。
- **功能需求**：用例图 + 用例表 + 文字描述。
  - 用例名 **动宾结构**（动词+名词），如"看菜谱""管理订单"。
  - 每个核心用例须有 **用例规约**（用例名、描述、主执行者、优先级、触发条件、后置条件、基本事件流、异常事件流）；**建议包含用例边界**。
  - 不要把所有用例都罗列，保持主次，非核心可放附录。
- **非功能性需求**：**量化指标**（响应时间、并发量、可用性百分比、CPU/内存阈值等）；必须在后文设计和测试中有对应体现；分类参考软件工程规范（可靠性、性能、安全性、可维护性等），不得自造名称。

### 2.5 第 4 章 系统概要设计

- **篇幅不可过短**；体现从需求到概要的递进。
- 关注 **Component 与 Connector**，不描述部件细节（那属于详细设计）。
- 先讲 **Why（设计依据）** 再讲 **How**；体现创新点。
- **4.1 系统静态结构（必须）**：
  - 推荐：**逻辑视图（组件图）**、**逻辑分层架构图**、**部署视图（部署图）**。
  - 功能模块图不属于 IEEE 4+1，不推荐，可并入逻辑视图。
  - 宜采用 **MVC**：类图区分 V（界面/接口类）、C（业务逻辑控制类）、M（数据实体类）。
- **4.2 系统动态结构（可选）**：进程视图/数据流图（进程视图非 UML 规范，不推荐），**推荐活动图、时序图**描述动态行为。
- **4.3 数据管理**：
  - 先说明存储选型依据（缓存 / 分布式 FS / 分布式对象存储 / 关系库…，为什么）。
  - 必含 **E-R 图，且关系要标出**；展示关系模型；数据库物理模型不必堆表。
- **4.4 其余（可选）**：安全视图、开发视图等。
- **功能模块图、架构图仅放在概要设计**，不放其他章节。

### 2.6 第 5 章 系统详细设计与实现

- 体现从概要到详细的精化。
- 每个模块须用 **活动图或顺序图** + 文字描述；设计阶段用顺序图/活动图，实现阶段用算法/流程图/伪代码。
- **同一业务流程，在不同章节采用不同表达方式（用例→顺序/活动→算法/伪代码）**，避免重复。
- **尽量少用流程图**；若用，开始/结束框两边半圆、中间直线。
- **正文中尽量少用代码**；若必须展示算法，用 **伪代码 + 文本框** 并定义为"算法 X-X"；配置用文本框装载定义为"图"。代码详写放附录。
- 详细设计应重点描述 **设计思想、设计模式、设计难点与特色**，不要记流水账。
- 使用开源框架时，**必须明确区分自己与已有框架的工作边界**，体现"如何基于"。

### 2.7 第 6 章 系统测试

必有测试环境 + 测试分析 + 测试用例设计 + 测试执行记录与结论。

- **6.1 测试概要**：测试对象、范围、环境（硬件/软件/网络/工具）、方法、目的、结论。
- **6.2 测试分析**：显性与隐性测试需求获取；按单元/集成/配置项/系统/验收/回归分类。
- **6.3 测试用例设计**：重点测试应给出 **两种及以上用例设计方法**（决策表、等价类、边界值、场景法…）；用例须含 **输入、输出、步骤、数据、判定准则、终止条件、期望结果**。
- **6.4 执行记录与结论**：测试覆盖分析、缺陷统计、残留问题；**灰盒测试** + **代码覆盖度**；重大 bug 的解决方式。
- **非功能需求必须有对应测试结果**（压力测试、稳定性、安全性、成熟性 DDP、容错性、易恢复性）。
- 不能以文字描述代替测试。

### 2.8 第 7 章 总结与展望

- 总结本人工作、贡献/特色、工作量，不得过于简单。
- **禁用夸大用词**：如"攻克""创新性设计""填补空白"等。
- 展望：改进方向、后续工作。

### 2.9 参考文献（GB/T 7714—2015）

- **真实有效、禁止编造**；**中英文文献兼备**；**有近期文献，最好含当年**。
- D 类（学位论文）须校名/所名；C 类（会议，线上除外）须会议地点；J 类（期刊）须 **卷(期)**。
- 正文引用：**上标**、顺序编号；**标号位于标点之前**；角标不得孤立居于行首；英文作者仅给 surname。
- 推荐 **顺序编码制**；参考文献页码必须完整。

### 2.10 致谢

- 致谢名字不出错；**不得用 AI 生成**。

## 三、排版与格式（细节清单，逐项对照自查）

### 3.1 页面与留白

- 页眉不出错。
- **每页留白最多 1~2 行**：图表过大可分页+续表头（续表 X-X）、调整图大小或图文排版顺序。

### 3.2 字体字号行距

- 全篇统一；每自然段首行 **左缩进 2 个汉字**。
- **中文正文不使用加黑**（加黑用于英文）；标题的"黑体"是黑体字体本身，非加粗。

### 3.3 图表（务必逐一检查）

- 编号规则：`图 3-1`、`表 3-1`（章号+序号），图表分别独立编号。
- **图编号在下，表编号在上**。
- 图表标题与图表本身必须同页，图不得打断段落。
- 图表居中、不出页边界；上下各留一空行。
- **字体不过大不过小**；图中英文尽量改中文；文字无重叠；截图必清晰。
- **表格使用三线表**；表中文字约为正文的半号；跨页必加"续表"。
- **禁用"如下图/下表所示"**；必须"如图 X-X 所示""如表 X-X 所示"并在正文中被引用。
- 引用他人图须标注来源。

### 3.4 公式

- 公式居中；与文字高度不齐时调整。
- 公式中所有符号须有说明。

### 3.5 标点

- 规范、不漏标点；引用标号在标点前（上标）。

## 四、LaTeX 模板（ustcthesis）避坑

### 4.1 初始化

- 从 USTC LaTeX 平台下载最新模板；**勿用 Safari 下载**（空格编码会导致平台编译失败）。
- 编译器：**XeLaTeX** 或 **LuaLaTeX**。
- `main.tex` 配置专业学位 + Windows 字体兼容：
  ```latex
  \documentclass[degree=master,degree-type=professional,fontset=windows]{ustcthesis}
  ```
- 封面改为隶书手写体：`ustcthesis.cls` 约 1896 行处，`figures/ustc-name.pdf` → `figures/ustc-name-stxingkai.pdf`。
- 去掉 `practice-supervisor` 注释以启用实践导师。
- 在 `chapters/` 下按章节分文件：`tech.tex`、`requirement-analysis.tex`、`HLD.tex`、`LLD&implement.tex`、`test.tex`、`summary&outlook.tex`。

### 4.2 图片与 UML

- 推荐 **PlantUML → PDF** 插入（矢量不失真）。
- 体积过大时：正文时用 `[draft]` 占位，定稿再生成。
- 若平台对某张长宽比极端 PDF 渲染失败，再用 PlantUML 导 PNG（注意英文字体以防中文错位）。
- 插图模板：
  ```latex
  \begin{figure}[htb]
    \centering
    \includegraphics[width=0.8\textwidth]{figures/xxx.pdf}
    \caption{图号、图题置于图下方}
    \label{fig:xxx}
  \end{figure}
  ```
- 引用：**必须 `如图~\ref{fig:xxx} 所示`**，不要"如下图所示"。
- 避免 `[h!]`，推荐 `[htb]`。

### 4.3 三线表

- 使用 `\toprule / \midrule / \bottomrule`，不随意改行距（影响封面等全局）。
- 自动换行列：`\begin{tabular}{p{0.2\textwidth} p{0.8\textwidth}}`。
- 单元格多行：`\multirow` 或内嵌 `\begin{tabular}{@{}c@{}}…\end{tabular}`。

### 4.4 英文文献大小写

- 默认作者全大写，若需仅首字母大写：在 `ustcthesis-numerical.bst` 搜 `#1 'uppercase.name :=` 改为 `#0 'uppercase.name :=`。

## 五、UML 建模规范（论文内图示准则）

### 5.1 图示使用矩阵

| 章节 | 推荐 UML 图 |
| --- | --- |
| 需求分析 | 用例图、用例表、活动图（业务流程）、时序图、状态图 |
| 概要设计 | 组件图、**分层架构图**、部署图、包图、类图（MVC 三类别） |
| 动态结构 | 活动图、时序图（推荐）；进程视图/数据流图不推荐 |
| 数据管理 | E-R 图（必须标关系）、实体图 |
| 详细设计 | 类图、顺序图、协作图、活动图、状态图 |
| 测试 | 无强制 UML；压力/覆盖率等用数据图表 |

### 5.2 PlantUML 美化脚本（推荐统一配置）

```plantuml
skinparam defaultFontName Times New Roman
skinparam classAttributeIconSize 0
skinparam style strictuml                  ' 时序图三角箭头严格 UML
hide empty description                      ' 状态图隐藏空描述
skinparam actorBackgroundColor #white
skinparam usecaseBackgroundColor #white
skinparam participantBackgroundColor #white
skinparam stateBackgroundColor #white
skinparam classBackgroundColor #white
```

### 5.3 关系表示（必记）

- Actor—Use Case：**不带箭头的实线**。
- 关联 `-->`、聚合 `o--`、组合 `*--`、继承 `--|>`、实现 `..|>`、依赖 `..>`、include/extend 用 `..>` 加 `<<include>>`/`<<extend>>`。
- 用例名：动词+名词；类名：名词；方法：动词短语。

### 5.4 图绘制注意（论文问题高频点）

- 图中英文尽量翻译为中文；字体不过大/过小。
- 图与图名同页；图不能打断段落；图上下空一行。
- 活动图推荐白底黑字；进程视图不推荐；功能模块图不推荐（可合并至逻辑视图）。
- 网络拓扑图不推荐，推荐 UML **部署图**。
- 流程图少用；使用时遵循标准形状（起止半圆）。

## 六、常见问题自查清单（对照修改明细）

写作/修改完成后，逐项核对：

- [ ] 正文 ≥ 3 万字，页数 60~80。
- [ ] 查重：初稿 <30%；定稿 <10%。
- [ ] 未使用"我/我们/本论文/本次论文"；一律"本文/本人"。
- [ ] 摘要四要素齐全，非产品说明书；<=600 字；留白<1/3 页。
- [ ] 英文 Abstract：paper→thesis/dissertation，关键词逗号分隔。
- [ ] 目录无单子节遗留；无"下图""下表"。
- [ ] 第 1 章有组织架构图（研究型）；国内外研究现状 ≥1 页、立足技术、有归纳。
- [ ] 第 2 章为"相关技术**分析**"，体现选型依据。
- [ ] 第 3 章无"模块"字样；Actor 具体化；用例名动宾；用例规约完整；非功能需求有量化。
- [ ] 第 4 章含组件图/分层架构图/部署图/E-R 图（关系标出），篇幅充足。
- [ ] 第 5 章每个模块有活动/顺序图 + 文字；正文无代码堆积；伪代码用文本框并命名为"算法"。
- [ ] 第 6 章有测试环境、两种及以上用例设计方法、代码覆盖度、非功能需求对应测试结果。
- [ ] 第 7 章总结具体、无夸大用词。
- [ ] 参考文献中英兼具、含近年/当年；D/C/J 类规范；上标顺序编号、标号在标点前；无孤立行首角标；页码完整。
- [ ] 除第 1 章、末章外每章有"本章小结"。
- [ ] 图表：编号正确、位置正确（图下表上）、同页、无超界、无字体重叠、来源已标、正文已引用。
- [ ] 公式居中、符号有说明。
- [ ] 字体字号行距统一；段首缩进 2 字；中文无加粗。
- [ ] 需求→概要→详细→测试 模块一致、顺序一致、无冗余。
- [ ] 致谢手写非 AI。
- [ ] 原创图（非系统截屏部分）均自绘。

## 八、工作流（推荐）

1. **规划**：按第二节章节结构列大纲，先确定模块划分，保证需求→设计→测试一致。
2. **建模**：用 PlantUML 先画用例图/活动图→类图/组件图→时序图/状态图，样式遵循 §5。
3. **撰写**：按章节顺序写，每章结束即落"本章小结"。
4. **排版**：使用 ustcthesis 模板（§4 避坑），图表编号/引用规范（§3.3）。
5. **自查**：对照第六节清单逐项检查；初稿查重 <30%。
6. **修改**：按问题明细统一改人称、术语缩写、图表、参考文献。
7. **定稿**：盲审格式（删个人/导师信息），查重 <10%。
8. **答辩**：打印 3 份；PPT 突出动机、方法、结果、工作量。
